# Finite structural satisfaction

The [product intent](intent.md), [comparison contract](resolved-ir-comparison.md)
and [requirements](spec.md#effective-structural-core-and-supported-fragment)
select the guarded 2014 structural fragment. The checker evaluates supplied finite
configurations; it does not generate instances, resolve source names/defaults,
interpret user expressions or invoke a solver.

## Effective input and domain

`Clafer.Semantics.EffectiveCore n` retains a finite declaration inventory, resolved
IDs, names, parent/super/reference edges, abstract flags and effective local/group
ranges. `WellFormed` reuses the MCS family discipline and adds unique IDs and valid
group ranges. `Supported` admits only user declarations and the synthetic root,
abstract basic heads without containment bodies and with unrestricted groups,
abstract supers with basic subtypes, user reference targets, and positive group
lower bounds only where a child inventory exists. Abstract local bounds are
unrestricted, or zero when no concrete descendant exists. Abstract inheritance
chains are allowed. Primitive targets, reference inheritance, concrete supers,
abstract references/bodies/groups and decision-pending source combinations remain
unsupported. Raw candidates can share objects across any head extents; satisfaction
separately enforces declaration disjointness.

`EffectiveCore.erase` projects an existing `Compile.Input` without constructing
authored/default provenance. `erase_wellFormed` and `erase_shape` preserve its
structural fields. `ConstraintFree` separately rules out expression attachments;
effective support alone cannot certify that expressions were absent from an AST.

## Meaning and interpretation

`StructuralSatisfies` is defined over sets and relations independently of the
algorithm. It requires typed endpoints, a singleton fresh root and used-object
coverage, inherited membership of the same object, abstract cover and disjoint
direct-subtype images, exactly one parent per parented membership, exactly one
target per reference head, set-reference pair uniqueness, local multiplicities
and concrete group counts. `DeclarationDisjoint` requires that any two heads
sharing an object be comparable through the reflexive transitive closure of super
edges. It applies across containment contexts and inheritance trees, regardless
of names or reference targets. Parent ownership remains per declaration.
`structural_reaches` derives root reachability from
these obligations and ranked containment/inheritance. `unused_abstract_empty`
derives empty abstract extents when no concrete descendant exists.

`Configuration.interpret` maps the canonical Compile role graph to the existing
bounded subset/span graph. Ordinary links are relation tuples. Parent maps are
inverses; target maps are pullback composites, retaining each reference head as
an occurrence even when parent and target coincide with another occurrence.
`headFiberEquiv`, `compositeFiber` and `composite_multiplicity` identify the counted
link fibers. `key_local_iff` relates pair uniqueness to the existing interpreted
Shape key. `abstracts_iff` relates the global abstract clauses to the existing
Cover and common-target Disjoint predicates with Q8.

`local_model_iff` proves both directions for the **exact** `Compile.localFormulas`
bank. `structural_model_iff` additionally includes the global root, abstract, group
and declaration-disjointness clauses: these are explicit whole-model obligations,
not declarations
claimed to be generated by local Shapes. `compiled_bank_iff` identifies the bank
of the actual constraint-free `Compile.compile` output. `erasure_correspondence`
and `equal_erasure_satisfaction` connect this selected compiled interpretation to
the effective core. `Compile.Input` retains declaration, name and metadata
obligations; arbitrary effective cores need not lift to an authored AST or valid
named CD. [Representative integration](representative-models.md) separately
connects concrete inputs to Compile and resolved-referent gluing.

`SpanModel.normalize` also starts from an arbitrary interpretation of the local
bank. Ordinary defaults, inverse, commutation and inclusion predicates derive
`headIso`, `derefIso`, `parentIso`, `targetIso` and `inheritedIso`; composite links
are transported rather than reduced. `normalize_satisfies` supplies the global
normalization bridge. `finite_model_representable` then encodes any finite model
in this domain, displaying an object bijection and an accepted candidate.
`structural_rename` preserves all obligations under object bijections; the span
isomorphisms preserve independent link renaming. These constructions do not
restrict the independently importable DPGraph library.

## Executable interface

`Candidate n` uses `Fin size` objects, one root, Boolean membership tables, and
Boolean containment/dereference relations. It allows empty classes and missing
or multiple endpoints. `realize` interprets these tables mathematically.
`inRange_card` equates finite counts with the existing embedding-based `InRange`,
including empty fibers and unbounded upper limits. `check_correct` states
`check m c = true ↔ StructuralSatisfies m (realize c)` with explicit well-formedness
and supported-fragment hypotheses. The implementation terminates by finite
quantification; large supplied universes can be expensive. `Ancestor` is defined
independently by super-edge closure. `ancestor_iff_iterate`, `iterate_bounded` and
`ancestor_iff_bounded` prove that a first visit takes fewer steps than there are
declarations, even on cyclic raw cores. The finite ancestry decision uses that
bound; it does not assume candidate satisfaction or admission.

The in-memory entrypoint is `run m certificate rawCandidate`. The certificate
contains parent/super ranks and unused-abstract flags, checked as ordinary data.
`admitted_wellFormed`, `admitted_supported` and `certificate_exists` prove soundness
and existence for every well-formed supported core. Bad rank/core data returns
`malformedCore`; failed fragment/unused-certificate checks return
`unsupportedOrInvalidCertificate`. This latter outcome alone does not prove that
no valid certificate exists. No satisfaction verdict is issued in either case.

Raw tables use arbitrary natural object labels and resolved declaration IDs.
Ordinary link identity is the typed tuple; reference occurrence identity is its
head object, distinct from the derived parent/target pair. `verify` checks, in
order: duplicate objects, absent root, duplicate membership, duplicate ordinary
links, unknown classes, dangling object labels and ill-typed endpoints. It then
returns `satisfies` or `violates`. Missing/multiple **typed** parent/target links,
root/cover/key/bound failures, incomparable declaration overlap and unused ambient
objects are semantic violations. Overlap diagnostics name `declaration_disjoint`.
No row is silently discarded: `decode_*`, `objectLabels`, `member_row_preserved`,
`link_row_indices` and `tuple_identity` establish fidelity, and
`success_tablesValid` proves successful verification entails table validity.
`verify_correct`, `verify_violation` and `run_correct` connect these public results
to the same semantics; malformed rejection is proved separately.

## Assurance and tests

Lean's kernel checks the correspondence theorems and positive/negative witnesses.
An ordinary native call runs the verified algorithm but is **not** a fresh
kernel-checked proof of that particular verdict. This interface claims no
per-instance proof certificates or verified native compiler/runtime.

[Examples](../Clafer/Verification/Examples.lean) and the executable
[test](../tests/structural_checker.lean) cover empty/zero/optional/exact/bounded/
unbounded counts, groups, nesting, shared inherited identity, abstract chains and
coverage/disjointness, malformed IDs/tuples/endpoints, typed nonfunctionality,
reference cycles, rejected unrelated/nested overlap, preserved group unions and
set/bag repeated targets. Test-only `collapseMutant` counts distinct targets and `upperBoundMutant` drops local upper
bounds; the unchanged optional-reference fixture rejects the real checker and
accepts each mutant. Both kernel witnesses and native assertions detect the
changed result. Full validation discovers these modules and tests, audits axioms
and imports, and replays the kernel; [trace artifacts](clafer-trace.md) name the
actual declarations. Validation evidence and acceptance review remain external.

## Pinned compiler input

The [resolved import protocol](resolved-import.md) connects the pinned compiler
export to this interface through checked UID indexing and fieldwise representation.
It derives admission hypotheses and preserves independent structural satisfaction;
compiler metadata and the unproved parser/capture boundary remain explicit.

## Bounded external comparison

The [comparison harness](bounded-comparison.md) reuses this checker and the strict
paired importer. Its independent enumeration and solver runs live outside the
public Lean imports. `ImportMain.failedPredicates` evaluates the existing checker
conjuncts to retain diagnostic predicate names. The checker theorem remains
unchanged; external SAT/UNSAT results and source-matched replays do not constitute
a universal compiler theorem or individual kernel proof certificates.
